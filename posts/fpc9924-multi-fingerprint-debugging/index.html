一枚指纹背后的两层 Bug：FPC 10a5:9924 多指纹录入排查

从 GUI 总是录入食指，到驱动把不同手指识别成同一个模板：记录一次 FPC 10a5:9924 多指纹故障的定位、修复与实机验证。
2026.11.13 1 分钟阅读 143 字
# Linux# libfprint# fprintd# Fedora# 故障排查

我原本以为只是指纹管理器列表显示不对：录入右手食指和中指后，界面上只看到食指。但进一步检查发现，右手食指和中指都能被设备识别。后来修复 GUI 后，第二次录入仍直接报重复。这个问题最终暴露出两层彼此独立的错误：一层在界面参数，一层在传感器驱动的身份匹配。

这篇文章记录我是如何把它们拆开、验证并修复的。

先区分“显示名称”和“实际录入的手指” #

Electron 界面的录入弹窗有一个可以编辑的“指纹名称”，但发给 fprintd-enroll 的手指参数一直固定为 right-index-finger。因此，即使把名称改成“右手中指”，系统实际执行的仍是：

fprintd-enroll -f right-index-finger "$USER"

这解释了为什么用户能编辑名称，却没有得到对应的中指模板。名称只是应用保存的显示元数据，不会改变 fprintd 操作的手指位置。

我把控件拆成“录入手指”和“显示名称”两项。前者决定传给系统的 FingerName，后者只用于卡片显示。选择变化时，操作提示和默认名称也一起更新。这个 GUI 修复随 0.1.1 发布。

命令行仍然报重复，说明问题不只在 GUI #

修完手指选择后，我用命令行尝试录入另一根手指：

Enrolling right-index-finger finger.
Enroll result: enroll-duplicate

这是一条很有用的边界验证：如果绕过 React 界面、直接调用 fprintd 仍然复现，那么继续调整弹窗名称或列表解析不会解决问题。问题已经进入 fprintd 与 libfprint 驱动这一层。

同时，fprintd 列表显示当前用户只登记了一根手指，而芯片枚举结果中仍然存在多条模板记录。主机登记列表和传感器内部模板并不总是一回事；清空 fprintd 用户记录，也不能据此断言芯片里没有历史模板。

根因：驱动把不同身份折叠成唯一候选 #

日志里找到的关键线索是：

accepting successful on-chip match for the only candidate despite identity mismatch

为了兼容设备的身份格式，旧驱动加了一条回退：芯片说“匹配成功”，而系统恰好只有一个候选模板时，即使芯片返回的身份和候选身份不相等，也把这个候选当成匹配结果。

设系统登记的身份是 A，另一根手指在芯片上的身份是 B。芯片返回 B 后，驱动仍把结果报告为 A。这样一来，fprintd 在录入前做重复检查时，会认为正在录入的手指已经存在；验证指定手指时，不同身份也可能被错误归到同一个候选上。

另外，早期代码会为芯片上已有的模板生成新的随机绑定身份。可传感器匹配时仍返回已有的原始身份，于是主机保存的别名和实际匹配身份逐渐分离。重复录入已有模板后再次调用保存命令，还会在这台设备上返回 Save DB failed: -13。

修复思路：保留身份边界 #

修复围绕“芯片返回的身份必须能对应到同一个模板”展开：

  1. 删除“只有一个候选就接受匹配”的回退。验证和识别必须比较真实身份；其他手指不能被当成已登记的那根。
  2. 重新登记芯片已有模板时，沿用传感器实际返回的身份，不再创建随机别名。
  3. 已在芯片中持久保存的模板不再重复执行保存步骤，避免固件返回 -13。
  4. 新模板保存后的刷新只接受与本次待确认身份精确相同的记录。
  5. 刷新 FpPrint 时先检查内部类型是否已经初始化，避免重复设置模板类型导致断言错误。

驱动回归测试使用真实的驱动回调、模板序列化和比较逻辑，只替换硬件报告与状态机边界，因此不需要连接指纹设备：

python3 scripts/test-fpc-identity.py ./libfprint-9924
meson test -C libfprint-9924/build-fpc9924 --suite unit-tests --print-errorlogs

测试先在旧逻辑上失败，再在修复后通过，覆盖了身份 A/B 的区分、多个候选识别、旧模板重新登记和刷新时的身份选择。

用两根手指分别验证 #

修复后的验收没有停在“编译成功”或“录入命令返回成功”。我先重新登记原有中指以更新历史身份映射，再把食指作为第二根指纹录入。随后检查列表并分别验证：

 - #0: right-index-finger
 - #1: right-middle-finger

右手食指：verify-match
右手中指：verify-match

这一步证实了两个模板可以同时保存，而且验证不会再把两根手指混为一个候选。

让录入过程可见 #

排查期间，旧 GUI 只显示一个持续旋转的等待动画；用户看不到采样进展，也不知道失败原因。0.2.0 将命令行的阶段结果实时传到界面：显示已接受的采样数、基于设备阶段总数计算的百分比，以及手指未居中、需要抬起、图像质量不足等重试提示。

进度只按设备反馈更新。设备未报告总阶段数时显示等待状态；达到采样数量也不会提前显示完成，只有录入命令确认成功后才到 100%。重复指纹、设备占用、权限或传感器错误会给出相应说明，并可以展开原始详情。取消操作会等待原生进程退出，避免传感器还被旧进程占用时立刻开始下一次操作。

新版加入扫描线、采样脉冲、环形进度、成功和失败动画，并遵循系统减少动态效果设置。9 项操作流测试和 Electron 界面验收覆盖了 IPC 进度、重试计数、旧事件隔离、成功、错误详情、取消、验证、深色模式和小窗口显示。

几点排查经验 #

  • 先验证输入实际传到哪一层：界面字段的名字不等于系统收到的参数。
  • 用命令行绕过 GUI，判断问题是否仍然存在；边界测试可以迅速缩小故障范围。
  • 分别核对应用元数据、fprintd 登记和芯片内部模板，不要把三种状态当成一个列表。
  • 指纹身份不一致时，不能为了兼容而猜测唯一候选；安全敏感操作必须保留身份边界。
  • 多指纹功能需要用至少两根手指同时录入并分别验证，单根手指的成功不足以证明实现正确。

本机已经安装修复后的 libfprint 驱动和 0.2.0 管理器。驱动改动位于 libfprint FPC9924 补丁仓库 ，管理器源码也在该仓库中。本文目前作为草稿保存，整理完成后再决定是否发布。
